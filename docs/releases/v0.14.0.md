# Nexa Platform v0.14.0

Local release preparation for executable frontend slices over the canonical
bounded contexts.

## Summary

Platform now supports an explicit runtime `mock` mode for deterministic `generic`
and `icisa` tenant demonstrations. `api` remains the default mode and existing
routes and REST contracts are preserved.

## Included

- BC-01 IAM, security and tenant/workspace administration for both demo
  profiles.
- BC-02 client-account reads and address/reference behavior.
- BC-03 tenant-aware catalog reads, catalog management, prices and promotions.
- BC-04 purchase-request, sales-order and manual-order demo adapters behind
  application ports.
- BC-05 inventory/availability and BC-06 fulfillment/delivery operational
  adapters, including reservations, dispatch workflow and POD.
- BC-07/BC-08 payment review and transfer fixtures; BC-09 documents/evidence;
  BC-10 notifications.
- Offline no-op change-feed adapter in mock mode; the existing SSE stream is
  retained for API mode.
- Functional baseline, mock-mode guidance and executable adapter tests.

## Explicit boundary

This release does not change the API, Blueprint or canonical bounded-context
definitions. Mock state is an in-memory frontend fixture and does not replace
backend persistence, authorization, jobs or webhooks. The release is a PRE-V1
functional foundation, not a claim of complete product migration or Production
Readiness.

## Validation

- Bounded-context, catalog-asset and Design Lab foundation validators: PASS.
- Unit tests: 156 passed across 78 test files.
- Production build: PASS; initial bundle `853.29 kB`, within the configured
  `880 kB` warning and `920 kB` error budgets after adding the operational mock
  slices.
- `npm audit --omit=dev`: zero production vulnerabilities.
- Local Playwright evidence: ICISA sign-in and client-account flow rendered
  without console errors.
