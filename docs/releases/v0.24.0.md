# Nexa Platform v0.24.0

Date: 2026-08-29

## Summary

This release closes a focused operational slice on top of the Design Lab
v1.0.2 presentation baseline: role-separated local validation personas and a
more useful, FEFO-oriented Inventory Lots view using the existing API-backed
projections.

## Included

- Local-only personas for Sales, Warehouse, Dispatch, Company Owner and Tenant
  Admin, mapped to the accepted backend roles and permission codes.
- `nexaDemoRole` documentation for deterministic visual/browser validation in
  explicit mock mode.
- Inventory Lots product and warehouse names/codes resolved from loaded catalog
  and warehouse data, with expiration-first presentation and readable fallback
  identifiers.
- Shared section-panel width constraints that keep wide tables inside their
  desktop/mobile page canvas while preserving table-level horizontal scrolling.

## Role and architecture boundary

- Dispatch is the visible UI label for canonical backend capability `LOGISTICS`;
  no separate `DISPATCH` backend role was introduced.
- The default runtime remains API-backed. Demo personas are consumed only by
  the explicit local mock-auth adapter and do not alter API authentication or
  authorization.
- `BOM` remains `OPEN`/`DEFERRED`: the accepted Product, Blueprint and API
  contract do not define a role, endpoint, entity or lifecycle for it.
- No new endpoint, entity, state, persistence model or cross-context contract
  was invented. Only Platform presentation/test documentation changed.

## Known limitations

- This is a focused Platform increment; it does not claim 100% product or
  pixel parity across every legacy screen.
- API live-runtime proof remains environment-dependent; this increment does not
  repair the pre-existing Flyway checksum drift or alter the database.
- Existing SCSS style-budget warnings remain for later focused maintenance.
