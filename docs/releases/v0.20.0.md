# Nexa Platform v0.20.0

Release record for role-separated API projections and explicit recovery from
partial operational source failures.

## Included

- The operations dashboard resolves the primary operational work area from the
  authenticated backend role and effective permission envelope.
- `WAREHOUSE` loads Warehouse projections only on its dashboard: warehouses,
  lots, movements and reservations.
- `LOGISTICS` loads the Dispatch/Logistics projections only on its dashboard:
  operations dashboard, Dispatch Orders and proof of delivery. Dispatch stays
  a capability of `LOGISTICS`, not a new role.
- Warehouse source failures preserve successful data, identify the failed
  source and expose a retry action.
- Company Owner read-only projections remain connected to the existing Sales,
  Customer, Warehouse and Logistics API ports. Each source is independently
  classified as ready, not granted or failed; retry reloads failed sources
  only and clears stale values after a failed refresh.
- Existing Design Lab shell composition, responsive layout and API-mode default
  are preserved while the new partial-data states use the established Nexa
  presentation primitives and tokens.

## Role boundary

| Role / capability | Frontend surface | API-backed responsibility |
|---|---|---|
| `COMPANY_OWNER` | Executive overview | Authorized read-only workspace projections |
| `SALES` | Commercial dashboard, Purchase Requests, Sales Orders and Client Accounts | Existing Sales and customer API ports |
| `WAREHOUSE` | Inventory and warehouse operations | Warehouses, lots, movements and reservations |
| `LOGISTICS` / Dispatch | Fulfillment and delivery operations | Operations dashboard, Dispatch Orders and POD |
| `BOM` | Not implemented | `OPEN`/`DEFERRED`; no accepted role or API contract |

Frontend visibility remains permission-backed and the API remains the final
authorization authority. No endpoint, entity, state or role was invented in
this release.

## Explicit boundary

- BOM is intentionally not implemented. The current accepted Blueprint/API
  baseline exposes no canonical BOM role, endpoint, entity or lifecycle.
- The API, Blueprint, Design Lab and Vue/legacy repositories were not modified.
- Mock adapters remain available for offline demonstrations only when
  `nexaDataMode=mock` is explicitly selected; the default runtime is API-backed.
- The local API bootstrap currently exposes the founder as
  `TENANT_ADMIN + COMPANY_OWNER`; the pure Company Owner browser case is
  therefore skipped locally unless a dedicated E2E fixture is supplied. CI
  provides and validates the dedicated fixture.
