# Nexa Platform v0.5.0

## Summary

Consolidated previously unreleased Identity, tenant, security and commercial vertical work. Intermediate planned versions were never published.

## Highlights

- Protected internal Angular surface with Company Administration, Client Accounts and Purchase Request operations.
- Lazy Catalog, Tenant Management and Sales features with dynamic route aliases preserving identifiers.
- Optimized initial bundle and focused facade, HTTP, route and accessibility-oriented tests.

## Functional capabilities

- Organization overview, workspace rename, teammate role/suspension/reactivation controls.
- Client Account list, filters, detail and management actions.
- Purchase Request inbox, filters, detail, timeline and review actions.

## Architecture

- Bounded-context pages keep their Application facades, Domain models and HTTP adapters separate.
- Business features load lazily; route aliases use explicit redirect functions for dynamic parameters.

## Security

- Internal roles are protected by the Platform surface and route guards; Buyer access is rejected.
- Session state stays in memory; API remains the authority for tenant, permission and concurrency decisions.

## UI changes

- Added accessible Company Administration actions and consolidated touched commercial surfaces while preserving existing Vue-derived structure.
- Structural parity has been advanced for implemented surfaces. Final decorative and pixel-level parity remains ongoing.

## Database migrations

None in this frontend repository; API `v0.6.0` owns the persistence contract.

## Docker

Modern Compose serves the optimized production build on `127.0.0.1:4200`; Legacy Vue remains a separate reference runtime.

## Validation

- `npm run validate:catalog-assets`.
- `npm test`.
- `npm run build` with no bundle-budget warning.
- `npm audit --omit=dev` and browser route checks.

## Breaking changes

Dynamic commercial aliases now preserve the concrete request identifier during navigation.

## Upgrade notes

Run `npm ci`, validate catalog assets, test and build before serving the static output. Use the API release for backend contract changes.

## Known limitations

- No Sales Order persistence or HTTP workflow.
- No inventory reservation.
- No dispatch.
- No invoicing.
- No cache tier.
- No production deployment.
- Final pixel-level Vue parity remains ongoing.
