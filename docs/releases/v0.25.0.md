# Nexa Platform v0.25.0

Date: 2026-08-29

## Summary

API-backed operational analytics evidence and API-only browser runtime.

## Included

- Period-scoped analytics controls send local calendar boundaries to the
  existing `GET /api/v1/logistics/operational-analytics` contract.
- On-time delivery rate is rendered from the server ratio as an explicit
  percentage, with fulfillment, document readiness and temperature indicators.
- A readiness snapshot exposes existing Logistics dashboard workload counts.
- Date validation and partial-source feedback preserve honest loading, error and
  recovery states.
- Browser runtime ignores mock switches; mock adapters remain isolated fixtures
  for unit/provider tests.

## Architecture and boundary

- Existing `OperationalAnalyticsSourcesPort`, Logistics API client and route
  composition remain the application boundaries.
- No new endpoint, entity, state, persistence model, dependency or cross-context
  contract was introduced.
- Dispatch remains the visual label for canonical backend capability `LOGISTICS`.
- `BOM` remains `OPEN`/`DEFERRED` because no accepted role, endpoint, entity or
  lifecycle contract exists.

## Verification

- `npm test -- --no-progress`: 85 files, 183 tests passed.
- `npm run build`: passed; existing component SCSS budget warnings remain
  non-blocking.
- Design Lab v1.0.2 foundation, catalog-asset and bounded-context validators
  passed.
- `npm audit --omit=dev`: 0 vulnerabilities.
- Pull request #61 CodeQL and both CI verification checks passed.
- Authenticated live API browser proof was not available during release
  preparation because the local API endpoint was not running; no mock proof is
  presented as API evidence.

## Known limitations

- This is a focused Platform increment. It does not certify 100% product or
  pixel parity across every legacy surface.
- Existing SCSS style-budget warnings remain for later focused maintenance.
- API live-runtime proof remains environment-dependent; this release does not
  repair database migration/checksum state.

## Release impact

- Platform version: `0.25.0`.
- Release follows repository GitFlow: feature branch → develop → release branch
  → main → annotated tag → GitHub Release → back-merge.
