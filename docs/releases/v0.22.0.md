# Nexa Platform v0.22.0

Date: 2026-08-29

## Summary

This release packages the current Platform visual-parity slice: Design Lab
v1.0.2 tokens and presentation patterns are applied to the API-backed B2B
client, catalog, warehouse, inventory and operational surfaces.

## Included

- B2B client accounts list and detail: commercial identity, buyer association,
  editable server-supported fields, delivery location and address book.
- Catalog list/detail: real catalog media, filter rail, price and availability
  states, cold-chain signals and detail navigation.
- Warehouse operations: warehouses/zones, lots, stock movements and
  reservations with metrics, dense tables, filters and explicit state handling.
- Dispatch analytics: fulfillment, document readiness, temperature health,
  status/route distributions, movement evidence and workload metrics from
  existing API ports.
- Profile, business documents and role-shell presentation refinements.

## Role and architecture boundary

- `COMPANY_OWNER`, `SALES`, `WAREHOUSE` and `LOGISTICS`/Dispatch continue to
  use the accepted permission model.
- Dispatch is still the visible projection of canonical `LOGISTICS`.
- `BOM` is intentionally not implemented: the accepted Product, Blueprint and
  API contract do not define its role or lifecycle.
- The cross-context analytics composition uses a local application contract;
  adapters are composed in `app.routes.ts`. No new endpoint, entity, state or
  persistence contract was invented.
- Only the Platform repository is included in this release.

## Verification

- `npm test -- --watch=false`: 84 files, 177 tests passed.
- `npm run build`: passed. Existing SCSS style-budget warnings are reported by
  Angular but do not fail the build.
- `npm run validate:design-foundations`: passed against Design Lab v1.0.2.
- `npm run validate:catalog-assets`: passed with 50 assets.
- `npm run validate:bounded-contexts`: passed for 11 roots and layer direction.
- `npm audit --omit=dev`: 0 vulnerabilities.
- Authenticated ICISA client-detail browser proof passed at desktop and 390px;
  the mobile viewport had no horizontal overflow.

## Known limitations

- Full credentialed E2E remains dependent on role-specific local fixtures; no
  dedicated fixture was available for this release run.
- Some existing SCSS budgets remain warnings and should be reduced in a later
  focused maintenance change.
- This release is not a claim of complete product migration, complete BOM
  behavior or 100% pixel parity across every historical screen.
